## Качественный разбор

1. `multifieldqa_en:3`: все три cache почти дословно
   воспроизводят верное определение ICD, примерно **88% F1**.
2. `:6`, `:10`, `:12`, `:13`: значения QA F1 совпадают
   между cache (примерно 59.3, 77.4, 66.7 и 33.3%).
3. `:4`: даже Dynamic включает не все эталонные слова,
   **25.6%**, а длинные переформулировки у g16/g64
   дают 31.6% / 37.0%. Это не доказательство, что они
   правильно отвечают лучше.
4. **`:7`** (эталон `Vice Admiral.`): Dynamic 100%,
   g16 **10.8%**, g64 **7.7%**. Все три предсказания
   начинаются с правильного звания; g16 и g64 затем пишут
   длинные пояснения, резко снижающие F1.
5. **`:8`** (эталон `15-3`): Dynamic и g16 дают 0%,
   g64 — 20.7%, но начало всех ответов неверно
   (`2–0` или `1-0`). В g64 оценка выше из-за
   совпадений слов в дополнительном тексте,
   а не восстановленного правильного счёта.

В этой маленькой выборке видна **чувствительность QA F1
к длине и формату ответа**, а не подтверждение того,
что сильная деградация retrieval у Qwen3-1.7B
повторяется для SmolLM3-3B на QA.

Сохранены оригинальные LongBench raw-промпты
без chat template и ограничение исходного датасета
по генерации (64 токена). Менять формат или лимит
можно лишь в *отдельной контрольной серии*.

## Как диагностировать постпроцессинг без GPU

Добавлен скрипт `src.diagnose_family_qa`, который
рассчитывает официальный F1 и F1 **первой непустой строки**
каждого сохранённого предсказания:

```bash
cd ~/kv-cache-longbench-pilot
git pull --ff-only
source cluster.env.example
python -m unittest discover -s tests -v
python -m src.diagnose_family_qa
```

Баллы только первой строки — **диагностические**,
их нельзя подменять официальным исходным QA F1
или считать заменой остановки генерации во время
инференса. Скрипт не перезаписывает JSONL.

## Следующий полноценный эксперимент

Поскольку Dynamic отвечает осмысленно на ряд заданий,
запускаем **80 подготовленных `multifieldqa_en`**
для Dynamic/g16/g64 (240 новых генераций).

На login-узле:

```bash
cd ~/kv-cache-longbench-pilot
git pull --ff-only
source cluster.env.example
export OTHER_MODEL_PATH="$(ws_find kv-cache)/models/SmolLM3-3B"
wc -l data/prepared/families/smollm3-3b/multifieldqa_en.jsonl
mkdir -p logs results/families/smollm3-3b/qa_en80
sbatch --export=ALL,OTHER_MODEL_PATH="$OTHER_MODEL_PATH" \
  slurm/smollm3_qa_en80.sbatch
```

После `COMPLETED 0:0` на трёх элементах массива:

```bash
wc -l results/families/smollm3-3b/qa_en80/*.jsonl
python -m src.score_family_qa
python -m src.diagnose_family_qa \
  --results-dir results/families/smollm3-3b/qa_en80 \
  --expected-n 80
```

Ожидаем три файла по 80 ответов. Анализ
`src.score_family_qa` проверяет идентичность задач,
token IDs hash и параметров для всех cache, считает
официальный F1 и парные bootstrap-интервалы.
Результаты QA нельзя напрямую объединять или
усреднять с retrieval_score.
