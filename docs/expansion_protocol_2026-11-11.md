**Серия expansion_v1: новые документы и перенос на HotpotQA.**

Аудит кластера сообщил о 159 JSONL и 7 669 распознанных записях без ошибок.
Доступны все 80 оставшихся retrieval EN context и 200 новых HotpotQA context.
[Предоставленные агрегаты аудита](../reports/expansion_v1_2026-11-11/audit_stdout_summary.json)
сохранены отдельно от полного JSON аудита, который остаётся на кластере.

Проверяем две гипотезы: сохраняется ли чувствительность к group size и prefill
на новых retrieval-документах; переносится ли она на multi-document QA.
HotpotQA выбран до получения новых ответов. Это отдельная серия при подавленном
refresh; она не изолирует эффект замены данных относительно прошлых r128-серий.

| Ось | Значения |
|---|---|
| Модели | Qwen3-1.7B, Qwen3-4B, SmolLM3-3B |
| Задачи | passage_retrieval_en, hotpotqa |
| Выборка | 80 новых exact context на задачу, один вопрос на context, seed 2031 |
| Cache | Dynamic, HQQ INT4 g16/g32/g64, оси 1 |
| Prefill | single_prefill, context_then_question |
| Условия | FP16/SDPA, native chat, thinking=False, residual=512 |
| Лимиты | вход 16 384, ответ 32 токена для обеих задач |
| Full | 48 ячеек × 80 = **3 840 новых ответов** |
| Smoke | 48 ячеек × 3 = **144 ответа** и 18 сверок с model.generate |

[Матрица](../experiments/expansion_v1.json). Для HotpotQA используется официальный
qa_f1_score с максимумом по эталонам; retrieval_score сохраняется отдельно.
Соответствие метрики и лимитов проверено по
[eval.py](https://github.com/THUDM/LongBench/blob/main/LongBench/eval.py) и
[dataset2maxlen.json](https://github.com/THUDM/LongBench/blob/main/LongBench/config/dataset2maxlen.json).

**Фиксация выборки до генерации.**

При первой подготовке скрипт повторяет проверку истории и требует совпадения
с `results/expansion_audit_2026-11-11.json`. Если история изменилась, подготовка
останавливается; нельзя молча подобрать другие документы. Для нового аудита
нужен отдельный `--output`, затем путь задаётся через EXPANSION_AUDIT_PATH.

Индексы и context hashes закрепляются в `data/prepared/expansion_v1/selection.json`.
Требуется ровно 80 разных context каждого набора и отсутствие пересечений
между наборами. После появления подготовленных входов эта же выборка повторно
не выбирается: плановые документы уже попадают в историю, но это не повод
сдвигать зафиксированный test set. Для всех моделей используются одни исходные
задачи, а для двух prefill-протоколов модели — одни полные token IDs.

Prepared/model manifests и raw JSONL не перезаписываются. Все старые серии
остаются отдельными. Подготовка требует прежних protocol_v1 manifests,
того же архива, локальных весов и официальных файлов LongBench; скачивания
весов или обновления окружения не требуется.

**Проверка длины и обрезания.**

Сделана локальная CPU-проверка с Hub-токенизаторами и закреплёнными revision;
[результат](../reports/expansion_v1_2026-11-11/tokenizer_precheck.json).
Это не проверка точных кластерных артефактов: их signatures сверяются отдельно.
Максимальный query block — 428 токенов, плюс 32 ответа: 460 < 512.
На кластере запас проверяется для всех вопросов до GPU-запуска, а счётчики
потом должны показать только исходную квантизацию K/V во всех слоях.

В этой предварительной проверке retrieval не обрезался; HotpotQA обрезается
до 16k на 24/80 входах Qwen и 10/80 SmolLM3. Такие вопросы не отбрасываются
и не заменяются после выбора. Основной анализ включает все 80 документов.
Заранее предусмотрен дополнительный анализ на общей для трёх моделей
подвыборке без обрезания (`untruncated_counts.csv`, `untruncated_contrasts.csv`).
Это помогает оценить чувствительность межмодельного сравнения к разным
tokenizer и границам видимого контекста, но не изолирует архитектуру от обучения.
Динамический baseline каждого внутримодельного сравнения видит те же token IDs.

**Запуск smoke на login-узле.**

```bash
cd ~/kv-cache-longbench-pilot
git pull --ff-only
module load python
conda activate kvcache
bash tools/start_expansion.sh smoke
```

Helper проверяет тесты, фиксирует выборку и готовит новые token IDs для трёх
моделей на CPU. При уже готовых manifests он проверяет входы. Затем отправляет
Slurm-массив 0–47, максимум два задания одновременно, по одной V100.
Порядок моделей: ячейки 0–15 Qwen3-1.7B, 16–31 Qwen3-4B, 32–47 SmolLM3.
Внутри модели retrieval single/split, затем HotpotQA single/split;
cache в порядке Dynamic/g16/g32/g64. Логи: `logs/lb-expansion-v1-<job>_<cell>.out/.err`.

После завершения всех 48 smoke-ячеек:

```bash
python -m src.score_expansion --phase smoke
```

Проверяется полная матрица, input/provenance fingerprints, неизменность
моделей/пакетов, отсутствие refresh, совпадение первого токена single quant
с Dynamic и 18 сверок ручного decode с model.generate. Различия Dynamic
single/split выводятся отдельно: редкие численные расхождения уже наблюдались
в прошлой полной серии и не означают ошибку квантования. Их нужно просмотреть
до full. Качество на трёх вопросах не используется для выбора cache.

Scorer также выводит грубую экстраполяцию времени генерации по smoke.
Она зависит от длин первых трёх вопросов и не включает загрузку весов,
GC, вывод логов и ожидание очереди; это не точный бюджет Slurm.

После успешных проверок и просмотра ответов:

```bash
bash tools/start_expansion.sh full
```

Helper до отправки сверяет текущий код со smoke, а каждый GPU-процесс проверяет
все условия своей smoke-ячейки. Полная серия автоматически не запускается.
После завершения:

```bash
python -m src.score_expansion --phase full
cat results/expansion_v1/summary/full/paired_contrasts.csv
```

**Анализ и ограничения.**

Результаты: `results/expansion_v1/{smoke,full}`; сводки — `summary/{smoke,full}`.
Основные контрасты — g64−собственный Dynamic и изменение потерь single→split;
дополнительные — g16/g32, все парные различия моделей для g32/g64 и общий
subset без обрезания. CI: парный document bootstrap, 2 000 повторов, seed 2026,
номинальные 95%, без коррекции множественных сравнений. Непопадание нуля
в один из множества интервалов не является самостоятельным итоговым выводом.

Изменение выбора, промпта, лимита ответа, residual или stopping policy после
просмотра smoke потребует отдельной серии. Независимость здесь относится к
сохранённой истории собственных экспериментов; exact hashes не обнаруживают
переводы/смысловые дубли и ничего не устанавливают о pretraining contamination.
Память, throughput и причинный эффект семейства требуют отдельных контролей.
